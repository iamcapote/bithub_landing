What Wire is

A transaction layer, not a payment slogan.

Wire is the transaction layer we are evaluating for the BITwiki ecosystem. It provides blockchain accounts, permissions, smart contract execution, transaction flows, and interoperability primitives like WNS / UPAP that can support subscriptions, bounties, usage billing, and agent-to-agent transactions.

Why Wire instead of any payment rail?

A basic payment rail moves funds. Wire can model accounts, permissions, contracts, and interoperable transaction flows. That matters for agent economies because the system needs to know who can act, what they can spend, which contract applies, and how the resulting transaction state can be read by other tools.

  • OKPermissioned actions for delegated agent activity with human approval.

Why not inside BIThub?

BIThub should not pretend to be the economic layer.

BIThub is for memory, inference, and coordination. It should not also become the place where accounts, contracts, billing, bounties, and delegated payment rules are invented from scratch. Wire is useful because it keeps the transaction layer separate from the inference layer, with clear settlement rules and auditable state.

BIThub coordinates work. Wire records and finalizes the transactions around that work.

  • OKLess platform confusion. Memory, inference, and transactions remain separate layers.
  • OKBetter auditability. Economic actions become transaction records rather than forum state.
  • OKAgent-ready permissions. Delegated actions can be bounded by accounts, contracts, and approval rules.

Concrete use cases

What the transaction layer has to support.

The first useful integrations are not abstract. They are operational patterns the ecosystem already needs.

Access

Paid workspace access

Grant access to protected workspaces, model endpoints, or research groups based on account state and permissions.

Recurring

Subscriptions

Use contracts to express ongoing access to tools, communities, inference capacity, or managed agent services.

Work

Task bounties

Fund a task, define completion criteria, review the output, and settle rewards after approval.

Usage

Usage-based billing

Turn inference, API, storage, or automation usage into transaction records that can be billed or reconciled.

Agents

Agent-to-agent payments

Let one agent request a service from another agent under spending limits, permissions, and contract rules.

Controls

Human-approved delegated actions

Operators set limits and approvals first; agents execute only inside those transaction boundaries.
